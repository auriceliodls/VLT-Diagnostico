1 Einführung 
IFE-Update 6.4 ist eine Software von Knorr Bremse, Division IFE, welche zum Überspielen von Software auf 
die Türsteuergeräte verwendet wird. Die graphische Benutzeroberfläche unterstützt dabei diesen Vorgang 
und zeigt alle nötigen Informationen über die Programmdatei und die Verbindung zum Türsteuergerät an.  
1.1 Spezielle Definitionen und Abkürzungen 
DCU Door Control Unit; Türsteuerung 
PMC Programmable motor control; 
Programmierbare Motor-Steuerung 
KCF Knorr Container File 
ETH Ethernet 
TFTP Trivial File Transfer Protocol 
HTTP Hypertext Transfer Protocol 
TCP Transmission Control Protocol 
IP Internet Protocol 
{Inatallationspfad} Eine Abkürzung für den Installationspfad von 
IFE-Update 6.4 
1.2 Funktionsmerkmale 
Die folgende Auflistung zeigt die Funktionsmerkmale von IFE-Update 6.4. 
• Die Suche nach angeschlossenen Türsteuergeräten mit ETH bzw. der seriellen Schnittstelle 
und die Anzeige derer Informationen. 
• Öffnen der Türsteuergerätsoftwaredatei, Überprüfung des Inhaltes und Anzeige der 
wichtigsten Informationen (z.B. Softwareversion, Prüfsumme) 
• Übertragung neuer oder modifizierter Türsteuergerätsoftware in die ausgewählten Geräte. 
• Einfügen einer Türsteuersoftware-Binärdatei in eine KCF Datei (nicht für FLEX DCU 
unterstützt). 
• Extrahieren von Türsteuersoftware-Binärdateien aus einer KCF Datei (nicht für FLEX DCU 
unterstützt) 
• Gleichzeitige Softwareübertragung auf mehrere Türsteuergeräte über Ethernet (TFTP, http 
(TCP/IP)) oder die serielle Schnittstelle. 
• Die Kommandozeilenschnittstelle von IFE-Update 6.4 ermöglicht die Einbindungen in andere 
Software bzw. Batch-Dateien. 
• Überprüfung auf Änderung der geöffneten KCF Datei durch andere Programme.

3 Bedienungsanleitung 
Dieser Abschnitt behandelt die Verwendung von IFE-Update 6.4 und die vorhandenen Features. Die 
Hauptfunktion von IFE-Update 6.4 ist die Übertragung einer Türsteuergerätsoftware in ein Türsteuergerät 
(DCU). Dies wird mit folgenden Schritten erreicht: 
1. Öffnen sie IFE-Update 6.4 mit dem Symbol am Desktop oder über den Start-Menü Eintrag in 
Windows. 
2. Öffnen sie die zu überspielende Datei (*.kcf) mit der Türsteuergerätsoftware über das Menü, dem 
Symbol in der Symbolleiste (siehe Abbildung 4) oder durch Ziehen der Datei aus dem Explorer in 
das IFE-Update 6.4 Fenster. 
3. Verbinden sie sich mit dem Türsteuergerät mit den Menüeintrag Aktion→Verbinden … (siehe 
Kapitel 3.2). Wurde das Türsteuergerät gefunden (bzw. mehrere Türsteuergeräte), wird es in der 
DCU Auflistung angezeigt. 
4. Haken sie diejenigen Türsteuergeräte in der Liste an, auf die die neue Türsteuergerätsoftware 
übertragen werden soll. 
5. Mit dem Menüpunkt Aktion→Datei übertragen … wird nun die Softwareübertragung gestartet. Der 
Fortschritt der Übertragung ist in der Statusanzeige der Türsteuergeräte sichtbar.  
6. Nachdem die Übertragung fertig ist überprüfen sie, ob die Softwareversion und Prüf summe der 
Türsteuergeräte mit der Softwareversion und Prüfsumme der KCF Datei übereinstimmt. Die 
Übereinstimmung wird durch einen grünen Hintergrund der Felder in der DCU Auflistung angezeigt 
(siehe Abbildung 5).

3.2.1 Ethernet 
Hinweis: 
Die Erfüllung der Systemvoraussetzungen aus Kapitel 1.3 (“Netzwerk-Konfiguration“) ist wichtig für 
einen erfolgreichen Verbindungsaufbau und sollte überprüft werden, wenn Fehler auftreten.  
 
Broadcast: Um alle Geräte, die mit dem derzeitigen Netzwerk verbunden sind, zu finden ohne eine 
IP-Adresse einzugeben, kann die Option Alle Geräte ausgewählt werden. Dabei werden Broadcast-
Nachrichten an alle Netzwerkgeräte gesendet mit der Anfrage, Informationen über die Türst euerung 
zurückzusenden. Geräte, die keine Türsteuerungen sind (PCs, Laptops, …) ignorieren diese 
Nachrichten. 
Damit diese Methode funktioniert, müssen ausgehende Broadcast-Nachrichten einerseits von der 
Netzwerk-Infrastruktur unterstützt werden und dürfen andererseits nicht von der Firewall des Service-
Computers (Kapitel 1.3) blockiert werden. 
Unicast: Um sich mit bestimmten Türsteuerungen mit einer bekannten IP-Adresse zu verbinden, kann 
die Option Benutzerdefiniert verwendet werden. Das Eingabefeld kann mit mehreren Einträgen 
befüllt werden, welche mit dem Zeichen „;“ voneinander getrennt werden. Ein solcher Eintrag kann 
entweder eine einzelne IP-Adresse sein, oder ein Bereich von IP-Adressen (zwei IP-Adressen, die mit 
„-“ getrennt werden). Ein Beispiel für eine gültige Eingabe befindet sich unter dem Eingabefeld. Um die 
Benutzbarkeit zu erhöhen, werden die zuletzt benutzten Verbindungseinstellungen gespeichert und 
können aus einer Liste ausgewählt werden.

3.2.2 Serielle Schnittstelle (RS232 / COM) 
IFE-Update 6.4 bietet auch die Funktion der Softwareübertragung über die RS232(COM) serielle

3.2.3 HTTP 
Eine ähnliche Funktionalität wie die unicast Ethernet-Verbindung wird durch die HTTP-Option 
geboten. Zur Eingabe der IP-Adressen wird dasselbe Text-Format verwendet (siehe Kapitel 3.2.1). 
Diese Verbindungsoption kann notwendig sein, wenn das Netzwerk keine TFTP -Uploads unterstützt, 
sondern nur TCP/IP-Kommunikation. Ein Broadcast an alle verfügbaren Geräte ist mi t dieser Technik 
nicht möglich. Es müssen einzelne IP-Adressen oder Adress-Bereiche eingegeben werden. Zusätzlich 
zur Adresse muss ein Port eingegeben werden. Der Standard-Port für http-Kommunikation ist 80, 
kann sich aber in verschiedenen Projekten unterscheiden. Weiters müssen ein Benutzername und ein 
Passwort zur Authentifizierung eingegeben werden. Schlägt die Authentifizierung fehl, wird die 
Türsteuerung nicht in der Liste der verfügbaren Geräte angezeigt. Wenn keine Authentifizierung nötig 
ist, können die Felder für Benutzername und Passwort freigelassen werden. Alle benötigten 
Informationen können aus dem Webserver-Beschreibungsdokument des Projektes entnommen 
werden. 
Vorsicht: Dieselben Einschränkungen für große IP-Adressbereiche, die auch bei der Ethernet unicast 
Verbindung gelten, gelten auch für die HTTP-Verbindung. 
 
Mit der Schaltfläche Verbinden kann nun die Verbindung aufgebaut werden. 
3.3 Verwendung des Boot Strap Loaders (MDC und PMC) 
Wenn eine ungültige oder beschädigte Software am Türsteuergerät läuft kann durch anhaken des 
BSL der Boot Strap Loader aktiviert werden. Im Falle eines älteren Türsteuergerätes muss eventuell 
ein Jumper in der Hardware gesetzt werden, um den BSL zu aktivieren. Bei den MDC 
Türsteuergeräten wird der BSL über die serielle Schnittstelle durch IFE-Update 6.4 aktiviert. 
Der Boot Strap Loader ist ein fixer Bestandteil des Türsteuergerätes und ermöglicht eine 
Softwareübertragung, wenn einer der folgenden Ereignisse eingetreten ist und eine normale 
Softwareübertragung nicht mehr funktioniert: 
• Das Türsteuergerät ist neu und die erste Softwareübertragung wird durchgeführt 
(normalerweise vom Hersteller). 
• Die Software im Speicher des Türsteuergerätes ist durch eine Unterbrechung des 
Programmiervorganges mit IFE-Update 6.4 (oder früherer Version) beschädigt oder ein 
Problem in der Software verhindert einen Verbindungsaufbau mit IFE-Update 6.4. Einige 
Gründe für eine beschädigte Software sind in der folgenden Auflistung angeführt und sollten 
vermieden werden: 
o Unterbrechung der RS232(COM) Verbindung während des Programmiervorganges  
o Unterbrechung der Stromversorgung des Türsteuergerätes während des 
Programmiervorganges 
o Eine beschädigte oder falsche Datei mit der Software wurde in das Türsteuergerät 
übertragen. 
o Die überspielte Software passt nicht zum Typ des Türsteuergerätes.

Datenerhalt  Bei einem FLEX Türsteuergerät kann die Option „Erzwinge Update 
aller Komponenten“ ausgewählt werden. Dieser Modus erzwingt ein 
Softwareupdate auch von kritischen Komponenten (z.B. Bootloader)

Dieser Update Modus ist nur zum Neuprogrammieren von 
Speicherkomponenten mit begrenzter Datenerhaltung zu verwenden 
(Stichwort „Data Retention“).

3.6 Kommandozeilenschnittstelle 
Dieses Programm verfügt über eine Kommandozeilenschnittstelle womit es aus dem Terminal-Fenster 
(cmd.exe), mit einer Batch-Datei oder von einem anderen Programm (z.B. eine 
Entwicklungsumgebung) aufgerufen werden kann. 
Wenn IFE-Update 6.4 bereits läuft und erneut mit Kommandozeilenparameter aufgerufen wird, werden 
diese Parameter an das bereits laufende Programm übergeben und von diesem verarbeitet.  
Die Kommandozeilenschnittstelle ist wie folgt aufgebaut (Groß-/Kleinschreibung beachten): 
 
IFEUpdate.exe  [--Filename <fn>] 
[--Connect [xxx.xxx.xxx.xxx] ;[COMx[BSL];] [/AutoStart] [/AutoClose]] 
[/CreateLanguageFileTemplate] [/SkipEqual] [/CompatibilityCheckOff] 
[/DataRetentionUpdate] 
 
--Filename <fn> Gibt die zu benutzende Datei an. Wenn die Datei keine KCF 
Erweiterung hat, wird diese automatisch in eine KCF Datei gepackt 
und in dasselbe Verzeichnis abgespeichert und von IFE-Update 6.4 
verwendet. 
--Connect <Verbindung> Übergibt IFE-Update 6.4 einen Verbindungsstring mit dem eine 
Verbindung aufgebaut werden soll. Wenn -- Connect 
255.255.255.255;COM1;COM3BSL angegeben wird, wird nach 
möglichst allen Türsteuergeräten über ETH gesucht. Zusätzlich wird 
eine Verbindungsaufbau über die seriellen Schnittstellen COM1 und 
COM3 initiiert, wobei für COM3 der Boot Strap Loader aktiviert ist. 
Die Verwendung von den Verbindungsvoreinstellungen CONN1, 
CONN2, CONN3 und CONN4 ist an dieser Stelle auch möglich. 
 Wenn über die serielle Schnittstelle eine Verbindung mit der FLEX-
DCU hergestellt werden soll, so muss vor der zu verwendenden 
COM Schnittstelle der Präfix „FLEX_“ verwendet werden (z.B. 
„FLEX_COM1“). 
/AutoStart Wenn die mit --Connect definierten Türsteuergeräte gefunden 
wurden, werden diese Geräte automatisch markiert und die 
Softwareübertragung gestartet. 
/AutoClose Wurde die Softwareübertragung auf allen ausgewählten Geräten 
beendet, schließt sich IFE-Update 6.4 von selbst. 
/CreateLanguageFileTemplate Mit diesem Parameter wird eine Vorlage für eine Sprachdatei 
({Installationspfad}\template.lng) erzeugt und anschließend IFE-
Update 6.4 geschlossen. Diese Vorlage kann verwendet werden um

4 Fehlerursachen und Fehlerbehebung 
Dieser Abschnitt soll Anhaltspunkte für die Suche von Fehlerursachen und deren Behebung bereitstellen. 
4.1 Verbindung zu einem Türsteuergerät kann nicht hergestellt werden 
Wenn sie den Verbindungsdialog in Abbildung 6 verwendet haben und das Türsteuergerät trotzdem 
nicht in der DCU Auflistung aufscheint (siehe Abbildung 4 und Abbildung 5) überprüfen sie die 
folgenden Punkte um das Problem zu lösen: 
Verbindung über ETH: 
• Überprüfung der Netzwerkverbindung von PC und Türsteuergerät 
• Wenn die Broadcastadresse (255.255.255.255) verwendet wurde, tragen sie die IP Adresse 
des gewünschten Türsteuergerätes im Textfeld Benutzerdefiniert des Verbindungsdialoges 
(siehe Abbildung 6) ein und verbinden sie erneut. 
• Wenn die Software am Türsteuergerät kein Ethernet bzw. kein Update über Ethernet 
unterstützt, wird dieses Gerät von IFE-Update 6.4 nicht erkannt. 
• Befindet sich das Türsteuergeräte gerade im Updatevorgang (d.h. Überspielung der Software 
in den Programmspeicher), kann dieses über Ethernet nicht erreicht und somit von IFE-
Update 6.4 nicht erkannt werden. 
Verbindung über die serielle Schnittstelle: 
• Überprüfung der seriellen Schnittstelle (wurde der richtige COM-Port ausgewählt; Kabel 
angeschlossen; ausgekreuztes serielles Kabel). 
• Deaktivieren sie den Boost Mode (siehe Abschnitt 3.4.2) und versuchen sie den 
Verbindungsaufbau erneut. 
4.2 KCF Datei kann nicht erzeugt werden 
Mit dem Menüeintrag Extras→KCF Datei erstellen können sie eine vorhandene Binärdatei der 
Türsteuerungsgerätsoftware in eine KCF Datei konvertieren. Wenn dieser Vorgang Probleme bereitet, 
kann einer der folgenden Punkte die Ursache dafür sein: 
• Die Datei beinhaltet keinen gültigen Informationsblock. Dieser beinhaltet die notwendigen 
Informationen über die Binärdatei für das Türsteuergerät. 
• Die KCF Datei existiert bereits und ist schreibgeschützt. 
4.3 Die Softwareübertragung ist fehlgeschlagen (falsche Prüfsumme und/oder 
Softwareversion, Zeitüberschreitung der Programmierung) 
Manchmal kann eine Softwareübertragung fehlschlagen. Die folgende Auflistung soll einige Hinweise 
liefern um dieses Problem zu lösen: 
• Versuchen sie die Übertragung erneut. Vielleicht war eine Störung der TFTP Übertragu ng die 
Ursache, dass das übertragene Programm fehlerhaft und deshalb die 
Prüfsummenüberprüfung die Aktivierung des Programmiervorganges und die 
Softwareaktualisierung verhindert hat. Dieser Überprüfung verhindert, dass eine beschädigte 
Software auf der Türsteuerung übernommen wird. 
• Wurde eine falsche Software übertragen (z.B. die Software ist für diesen Türsteuerungstyp 
nicht gedacht; keine Netzwerkunterstützung; keine Ethernet-Update Unterstützung), kann die 
Software eventuell nicht richtig arbeiten und deshalb eine Zeitüberschreitung 
Programmierung Meldung hervorrufen. In diesem Fall kann nur eine Programmierung über 
die RS232 Schnittstelle das Problem beheben (siehe Abschnitt 3.2).

Falls der Aufruf von IFE-Update 6.4 über die Kommandozeile Probleme bereitet, überprüfen sie die
