1 Introduction 
IFE-Update 6.4 is a Knorr Bremse, Division IFE software which is used to upload new door control unit 
software into the door control unit hardware. The graphical user interface shows all required information 
according the software file and the connected door control units. 
1.1 Specific Definitions, Acronyms and Abbreviations 
DCU Door Control Unit 
PMC Programmable motor control 
KCF Knorr Container File 
ETH Ethernet 
TFTP Trivial File Transfer Protocol 
HTTP Hypertext Transfer Protocol 
TCP Transmission Control Protocol 
IP Internet Protocol 
{Installation Path} An abbreviation for the installation path of 
IFE-Update 6.4 
1.2 Features 
Following list shows the main features of IFE-Update 6.4. 
• Search for connected DCU’s with ETH and the Serial Ports and show their states 
• Open the DCU software file, check the content and show all required information (e.g. version 
number, check sum) 
• Upload new or modified DCU software into the selected DCU’s 
• Merge a DCU binary file into a KCF (not supported for FLEX DCU) 
• Extract a DCU binary from a KCF (not supported for FLEX DCU) 
• Parallel software upload to multiple DCUs using ethernet (TFTP, HTTP (TCP/IP)) or the serial 
port 
• Command line interface to include IFE-Update 6.4 into tool chains 
• KCF File observation on changes

the same subnet address-range as the DCUs. The configuration of a static IP is different for many 
systems and therefore not covered by this document. Please contact your local IT department.

3 Program Operation 
This section treats the usage of IFE-Update 6.4 and the available features. The main function of IFE-Update 
6.4 is to upload new DCU software into the DCU hardware and this is achieved with the following steps: 
1. Open IFE-Update 6.4 with the icon on the desktop or in the Start-Menu of Windows. 
2. Open the file (*.kcf) with the new DCU software. 
3. Connect to the DCU with the menu entry Action→Connect … (see Chapter 3.2). If the desired DCU 
was found it is listed in the DCU list. 
4. Select the DCU’s that should be updated with the new DCU software. 
5. Use Action→Upload to Device to initiate the software upload. 
6. After the upload has finished check if the software version and the checksum of the selected DCU’s 
are equal with the DCU software file. The equality is indicated with a green background color of the 
software version and the checksum cell (see Figure 4 and Figure 5).

Use the menu entry Action→Connect … or the corresponding icon in the toolbar (see Figure 4) to 
open the Connection-Dialog illustrated in Figure 6. There you can select different ways to establish a

3.2.1 Ethernet 
Important Notice: 
The fulfillment of the system requirements in chapter 1.3 (“NETWORK CONFIGURATION”) is 
important for a working communication and should be checked, if any errors are encountered. 
 
Broadcast: If you want to find all available devices connected to your current network without entering 
an IP address, use the option All devices. This will send broadcast messages to all devices in the 
network with the specific request to send back information about the DCU. Other non-DCU devices 
(PCs, …) will ignore this message.  
For this method to work, outgoing UDP broadcast messages must be supported by the network’s 
infrastructure (chapter 1.4) and must not be blocked by the firewall of the maintenance PC/laptop 
(chapter 1.3). 
Unicast: If you want to connect to DCUs with specific IP addresses, you can use the option Custom. 
The textbox can be filled with multiple entries separated by “;”. An entry can either be a single IP 
address, or a range of addresses (two IPs separated by “-”). An example connection string is 
illustrated below the text box. To improve the usability the last used connection strings are stored and 
can be selected using the drop-down button of the text box. 
Caution: Using very wide ranges of addresses (e.g. more than 1000) will slow down the application 
significantly, because many unicast messages have to be sent separately, whereas a broadcast takes 
advantage of the network infrastructure. 
3.2.2 Serial Connection (RS232 / COM) 
IFE-Update 6.4 also provides a software upload via the RS232(COM) serial port. To use this feature, 
select RS232. Then select the DCU type and the corresponding COM-Port (the combo box lists all 
available ports). 
3.2.3 HTTP 
Similar functionality as in the unicast ethernet connection is provided by using the HTTP option . It uses 
the same input format as ethernet unicast IP addresses. This option can be necessary, if the network 
does not support TFTP uploads, but only TCP/IP communication. A broadcast to all available devices 
is not possible with HTTP, so single IPs or ranges of IPs have to be entered.  Additional to the IP 
address a port has to be entered to be able to connect. The default port for HTTP-communication is 
80, but it can be different for some projects. The needed port is found in the webserver description 
document. 
Furthermore, a username and a password have to be entered for authentication. This information can 
also be found in the webserver description document. If the authentication is not successful, the DCUs 
will not show up in the device list. If no authentication is required, the fields for username and 
password can be left empty. 
Caution: The same restrictions for very wide IP ranges, like with the ethernet unicast connection, also 
apply for the HTTP connection. 
 
Use Connect to open the connection. 
3.3 Usage of the Boot Strap Loader (MDC and PMC) 
If you have an invalid or damaged firmware on the DCU, use the BSL check box to connect with the 
Boot Strap Loader. In the case of an older DCU, check if a jumper on the hardware has to be set to 
enable the BSL. In the case of an MDC the BSL is activated via a pin of the serial port by IFE-Update 
6.4. 
The Boot Strap Loader is non-volatile implemented within the DCU and allows uploading firmware into 
the DCU if one of the following points occurred and a normal software upload doesn’t work: 

--- Update-Manual-English.pdf | PÁGINA 11 ---
Software-Manual IFE-Update 6.4 E403420P64_EN - Issue “00” 
 Page 11/21 
 
• The DCU is new and the first firmware upload is done (normally by the manufacturer). 
• The firmware in the memory is damaged due to an interrupted programming process with IFE-
Update 6.4 (or earlier versions) or a problem within the firmware denies a connection with IFE-
Update 6.4. Some reasons for a damaged firmware in the memory are listed in the following 
and they should be avoided: 
o interrupting the RS232(COM) connection during the programming 
o switching of power supply during the programming 
o a damaged or wrong software file was programmed into the DCU 
o the target of the firmware and the DCU type does not match 
The Boot Strap Loader can be used with the RS232(COM) serial port. The procedure to activate the 
Boot Strap Loader depends on the DCU type: 
• FLEX: 
o The FLEX DCU does not support the Boot Strap Loader mechanism!  
• MDC: 
o Activate the checkbox use BSL in the connection dialog (see Figure 6), select the 
corresponding RS232(COM) serial port and press Connect. 
o Switch OFF the power supply of the DCU (if not already done) as written in the state 
field in the DCU-List (see Figure 4). 
o Switch ON the power supply of the DCU as written in the state field in the DCU-List 
(see Figure 4). 
o Boot Strap Loader should be activated and the connection to the DCU should be 
established. Then upload the DCU software as usual. 
• PMC: 
Some of the PMC DCU types don’t have a Boot Strap Loader. The other PMC DCU types 
have a jumper inside the electronic to activate the Boot Strap Loader. In both cases contact 
IFE for support.

3.6 Command Line Interface 
The program can be called and controlled via command line arguments. This feature allows you to 
start the program from the terminal window cmd.exe, within batch files and to include the program as 
extern tool to other programs like IDE’s. 
If an instance of IFE-Update 6.4 still runs and you start another instance with new arguments, these 
arguments are passed to the running instance and processed by it. 
For the Command Line Interface use the following syntax (case-sensitive): 
 
IFEUpdate.exe  [--Filename <fn>] 
[--Connect [xxx.xxx.xxx.xxx];[COMx[BSL];] [/AutoStart] [/AutoClose]] 
[/CreateLanguageFileTemplate] [/SkipEqual] [/CompatibilityCheckOff] 
[/DataRetentionUpdate] 
 
--Filename <fn> Assigns the path and name of the file to be used. If the file has not a 
KCF file extension, the file is merged into a KCF in the same 
directory and this KCF is used by IFE-Update 6.4. 
--Connect <connectionstring> Forces IFE-Update 6.4 to open a connection with the given 
connection string. Consider, if you use  
--Connect 255.255.255.255;COM1;COM3BSL, 
a broadcast is used to list all DCU’s which could be found. 
Additionally, the serial ports COM1 and COM3 are used to connect 
to DCU’s. With the appendix BSL the Boot Strap Loader is used to 
establish the connection on COM3. In general, if the DCU with the 
passed IP-Address/COM is found, it would be automatically selected 
(this would not happen if a broadcast is used or one of the 
connections is not established). 
 If a connection with a FLEX DCU should be established via a serial 
interface, the prefix “FLEX_” needs to be added before the COM 
interface that should be used (e.g. “FLEX_COM1”). 
/AutoStart If the DCU’s defined with --Connect are found and selected, the 
upload of the DCU software starts. 
/AutoClose This option defines, that IFE-Update 6.4 is closed automatically after 
all selected devices have finished the software upload. 
/CreateLanguageFileTemplate This option creates the language file template {Installation 
Path}\template.lng and closes IFE-Update 6.4. This template file 
can be used to create a new translation for the IFE-Update 6.4 
interface. 
/SkipEqual This option defines, that the software upload is skipped if the correct 
software is already loaded in the DCU (i.e. software version and 
CRC matches). 
/CompatibilityCheckOff With this parameter the compatibility of the DCU type and the 
software that should be flashed is not checked. 
/DataRetentionUpdate With this parameter the setting “Data Retention” is set for FLEX 
DCUs (see 3.4.4 “Data Retention“). As a result, the software update 
procedure will also update critical components (e.g. Bootloader). 
Use this option with care, as the DCU can get functionless in case of 
a loss of power supply during software update with this mode 
enabled. 
Example:  IFEUpdate.exe --Filename C:\E123456.A01.kcf 
--Connect 255.255.255.255;COM1BSL;CONN3 /AutoStart

4 Troubleshooting 
This section treats some possible troubles and potential troubleshooting.  
4.1 Can’t connect to a specific DCU 
If you use the connection dialog (see Figure 6) and the desired DCU was not listed in the DCU list of 
the main window (see Figure 4 and Figure 5), check the following points which might help to solve the 
problem: 
Connect via ETH: 
• At the first check the network connection of your PC and the DCU. 
• If you used a broadcast (255.255.255.255) and the DCU was not found, use the IP address of 
the DCU to connect (option Custom in Figure 6). 
• If the DCU (software version) does not support a firmware update via Ethernet, the DCU does 
not respond on the requests from IFE-Update 6.4 and so it would not be found. 
• Maybe the DCU currently executes a firmware update. During this time the DCU cannot be 
reached via Ethernet. 
Connect via RS232(COM): 
• Check the correctness of the serial connection (correct RS232(COM) port number; cable 
connected; crossed serial cable) 
• Deactivate the Boost Mode (see subsection 3.4.2) and try the connection again. 
If these points did not solve the problem, try to use the Boot Strap Loader as described in section 3.3 
to establish a connection to the DCU and to upload the DCU software. 
4.2 Problem to create a KCF 
With the menu entry Extras→Create KCF File you are able to convert a DCU binary into a KCF. If the 
conversion troubles, one of the following points might be the reason: 
• If the binary file does not contain a valid info header which contains the information about the 
binary, the binary file is invalid. 
• The KCF target file still exists and is write-protected. 
4.3 DCU Software upload failed (wrong check sum and/or software version, Flash 
process timeout) 
Sometimes it might happen that a software upload and so the software update fails. The following list 
will give you some hints to solve the problem: 
• Try the upload again. Maybe the TFTP transfer had troubles and so the check sum of the 
transferred file was wrong. In this case, the DCU does not activate the firmware update to 
prevent the use of damaged software. 
• If the wrong software was transferred (maybe wrong DCU type or software without TFTP and 
update via ETH support) it might happen that the software does not work and the DCU does 
not respond (Flashing Timeout). In this case, the only way to fix the problem is to transfer the

4.4 Troubles with the Command Line Interface 
If the use of the Command Line Interface from IFE-Update 6.4 makes troubles, check the following list 
that will gives you some hints to solve the problem: 
• Check the syntax of the command as described in subsection 3.6. Also consider the case-
sensitive arguments. 
• Check the file path of IFE-Update 6.4 and the filename passed as argument. 
• If the file path of the executable or the passed filename contains whitespaces, this file path 
have to be quoted. 
Example: 
"C:\Program Files\IFE\IFEUpdate\IFEUpdate.exe" 
--Filename "D:\Project A\E123456.A01.kcf"
